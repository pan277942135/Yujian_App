## 分层审查结论

- 现有层级统计保持 `L1=2 / L2=26 / L3=38`，与既有目录与用户测试配置一致；保留这一统计不代表分层均合理，也不代表覆盖已经充分。
- L1 仅覆盖 Processing 状态机早到事件与 Timeout/Retry 状态合同；不能替代 CameraX、系统权限、真实模型、视觉或生命周期验收。
- L2 26 条必须使用受控 UI/故障接口隔离外部设备、模型与存储；控制结果需始终标 `controlled=true`。
- L3 38 条必须在 API28 指定目标运行并采集实际设备 profile；其中相机路径、相册模型路径、系统权限 Host、设备 UI 和人工视觉审核属于不同执行合同，不能把每条 L3 统称为真实 CameraX E2E。
- `REAL_MODEL_GALLERY` 使用真实图片和生产 Detector/Crop/Classifier；不预设分类结果。`DEVICE_CAMERA_ONLY` 只证明相机/拍摄链路，不证明模型表现。
- IMG-02/03/05/06/07 缺少获批输入，相关用例的定义可审查，但执行条件依赖资产关闭；IMG-01/04 当前仅为候选。图片详情见 [`07_IMAGE_FIXTURE_AUDIT.md`](07_IMAGE_FIXTURE_AUDIT.md)。
- `PROC-07` 行为已冻结，但数值参数尚未批准；阶段用例只能针对“批准配置值”定义测试逻辑，当前配置 Gate 是 `BLOCKED_PARAMETER`。
- `NAV-07` 行为已冻结，但同一 owner 安全恢复须以真实 device evidence 证明；没有秒数阈值替代 owner/文件完整性判断。

## 机器字段一致性

- 每条 case 均有唯一 `planned_test_method`，66/66 方法名不重复。
- `input_id` 是主输入（nullable）；原 `input_ids` 数组保留多输入完整映射。
- 旧 `test_layer/execution_mode/steps/assertions/evidence_required` 保留兼容；新增 `execution_contract` 是细分后的规范执行方式。
- 任何 `expected_timing_assertions=[]` 表示此 case 没有声明新的时长阈值，并不表示耗时 PASS。
- `pass_criteria` 是将来验收规则；它不改变当前执行状态。执行报告必须与当次 source SHA、APK SHA、输入 SHA 和实测设备绑定。

现有只读目录校验器仅验证 catalog 结构、批准七项不变、单初始用户、66 ID、输入绑定、反向用户索引和 NOT_RUN；其 PASS 不等于 Android Build、Instrumentation、模型或 Runtime PASS。
