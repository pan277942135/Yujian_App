## 1. 核心结论：四类职责，不由一个模型包办

| 业务问题 | 决策责任 | 输入 | 输出 | 不负责什么 |
|---|---|---|---|---|
| 是否有鱼 | **DET_FISH 检测器 + 输入质量门 + 检测结果规则** | 方向归一化后的完整场景图 | 零个或多个候选鱼体框、检测分数、检测状态 | 不负责判断鱼种 |
| 鱼在哪里 | **DET_FISH 检测器**，再经坐标映射/边界校验 | 完整场景图 | BBox、坐标系、原图映射关系 | 不把分类器的显著区域当作正式检测框 |
| 鱼是否过小、是否能可靠识别 | **几何/质量规则与可分类性门** | BBox、原图尺寸、质量状态、裁剪可用性 | 可继续分类、尺寸警告、或输入恢复原因码 | 不单凭分类分数倒推鱼体大小 |
| 是什么鱼 | **MODEL_M1 鱼种分类器** | 从有效 BBox 得到的鱼体 Crop | Top-K 鱼种候选及分类分数 | 不负责在完整场景中找鱼，也不单独判定“无鱼” |
| 最终显示什么结果 | **业务结果融合层** | 检测状态、质量/尺寸原因、分类输出、运行错误 | High / Medium / Low、No Fish、Image Quality、Technical Failure 等既有结果分支 | 不把技术失败伪装成无鱼或照片差 |

## 2. 端到端主流程

1. **拍照 / 相册选择**：接收用户拍摄或选择的原始完整场景图。原始图像与识别过程使用的归一化图像必须可追溯；不得用 Accepted Pool 的分类 Crop 替代检测器原图。
2. **预处理**：读取 EXIF 方向，按统一方向解码；记录原图尺寸、归一化尺寸与变换关系。若发生旋转、缩放或裁剪，后续 BBox 必须映射回对应图像坐标系。
3. **输入质量门**：判断是否可继续处理，状态语义为 GOOD / WARNING / INVALID。INVALID 必须进入恢复路径；WARNING 是否继续由既有合同决定。质量不足时不能仅因为检测器没有框就断言“无鱼”。
4. **DET_FISH 检测**：将完整场景图送入检测器。输出零个、一个或多个鱼体候选框及检测分数。生产使用的模型版本由当前运行配置决定；模型测试页验证版不能自动等同于生产默认版本。
5. **BBox 坐标映射与有效性检查**：校验坐标范围、正面积、边界、尺寸语义和图像变换关系。保留归一化 BBox、像素 BBox、source size 与 crop rectangle 的来源关系，避免旋转/缩放造成框偏移。
6. **鱼体尺寸 / 可分类性门**：使用 BBox 像素宽高、面积占比、边界截断、输入质量和 Crop 可用性评估是否具备足够鱼体信息。具体阈值必须读取当前有效合同/代码；本文件不另行冻结新阈值。
7. **Crop**：只从已校验的完整场景图按有效 BBox 生成鱼体 Crop。裁剪边界补偿、留白、边界夹取与 EXIF 变换须遵循当前图像裁剪合同。Crop 失败是技术错误，不是“无鱼”。
8. **MODEL_M1 分类**：只对符合分类条件的 Crop 做鱼种分类，输出 Top-K、分数及模型版本。分类器分数不是校准后的“识别正确概率”，不得向用户伪装为准确率。
9. **结果融合**：将鱼体证据、尺寸/质量原因、分类候选与运行错误按既有 RR07 判定逻辑融合。分类置信度不能覆盖检测失败、输入无效或技术异常。
10. **识别结果 / 恢复**：进入既有 Result High / Medium / Low、Issue No Fish / Image Quality，或独立的 Technical Failure 恢复路径；用户可修改鱼种，确认后再保存鱼获。

## 3. 关键分支与优先级

### A. 图像质量无效

- 输入解码失败、方向/尺寸无法可靠处理或质量门判定 INVALID：进入图像恢复路径。
- 不运行或不信任后续模型输出；不输出确定鱼种。
- 不得把解码、模型加载、Crop 或推理异常归因为用户照片质量。

### B. 没有有效鱼体框

- 只有在输入足以判断、检测器正常完成且既有检测尝试策略结束后，才可进入 **ERROR_NO_FISH**。
- 如果输入本身不足以支持可靠判断，应进入 **ERROR_IMAGE_QUALITY**。
- 如果模型/运行时失败，应进入 **TECHNICAL_FAILURE**，不能伪装为 No Fish。

### C. 检测到鱼，但鱼体过小或 Crop 不可用

- 尺寸门依据几何尺寸与当前质量规则判断，不由分类器决定。
- 如果现有规则判定不具备分类资格，进入既有 Image Quality 恢复分支，并保留可解释的内部原因码，例如 `FISH_TOO_SMALL`。
- 如果仍可分类但物种证据不足，应由既有分类判定进入 Low / Medium，而不是把所有小鱼一律判为无鱼。
- `FISH_TOO_SMALL` 是内部诊断原因，不在本文件中新增独立的用户可见产品状态。当前 Result 的 3+2 结构及 RR07 权威优先。

### D. 检测成功，分类结果不同

- **High**：符合当前有效判定合同的默认推荐；Top-1 仍可被用户修改，不等于事实保证。
- **Medium**：候选鱼种存在歧义；Top-K 只是建议，用户确认前不能当作已确认鱼种保存。
- **Low**：鱼体存在或合理疑似存在，但没有足够证据可靠断言鱼种；允许进入现有手动选择流程。
- 分类阈值、候选差值与检测质量的交互必须读取当前 RR07 与精确运行时实现；本文件不复制/另设一套阈值。

### E. 多鱼、边缘截断、旋转与异常

- 多个候选框：按现有主鱼选择/多鱼处理合同处理；不得默默把任意候选当作用户目标。
- 鱼体触边或不完整入画：作为独立检测质量信号保留；不能只根据分类分数宣布 High。
- 方向恢复、坐标映射和裁剪都必须使用同一图像变换链。
- Technical Failure 与用户主动 Back 是不同出口；Back 不等于失败，也不应自动保存。

## 4. 两个核心模型的输入/输出合同

### DET_FISH · 鱼体检测器

- **输入**：方向归一化后的原始完整场景图。
- **输出**：候选鱼体 BBox、检测分数、候选数量及推理状态。
- **训练数据类型**：完整原图 + 人工确认的 `accepted_bbox`；负样本为人工确认无鱼的完整场景图。
- **不允许**：直接把分类器 Crop 当作完整场景检测输入；把 `detector_bbox` 候选标签代替人工 accepted_bbox；用模型故障代表 No Fish。
- **版本规则**：DET_FISH_v0.3 已有训练产物，但模型测试页面可选性、独立测试集结果和真实推理必须分别提供证据。生产默认模型只有经过独立授权与精确版本验收后才能变更。

### MODEL_M1 · 鱼种分类器

- **输入**：由经过验证的鱼体 BBox 从完整原图裁剪得到的 Crop。
- **输出**：Top-K 类别与分类分数。
- **职责边界**：它只回答“这个 Crop 最像哪些已知鱼种”，不回答完整场景里是否存在鱼，也不修复错误 BBox。
- **版本规则**：实际分类模型版本从当前运行配置读取；此流程文档不擅自指定或升级分类模型版本。

## 5. 用户可见 Processing 与内部技术步骤的映射

产品 Processing 已冻结为三个用户可感知状态。检测、坐标映射、尺寸判断、Crop 和模型推理是内部技术步骤，不得各自扩展成新的加载文案或产品状态。

| 产品状态 | 技术含义 | 视觉边界 |
|---|---|---|
| 图片识别中 | 预处理、理解完整场景、检测鱼体 | 原图保持主导；不能提前显示鱼种、候选或置信度 |
| 已定位到鱼体 | 已有有效鱼体定位证据 | 鱼体成为视觉焦点；不得把人工参考轮廓冒充生产检测 Mask |
| 鱼种识别中 | 对有效 Crop 进行鱼种分类与结果准备 | 不提前揭晓鱼种，不显示假百分比 |
| RESOLVE | 内部结果收口转场 | 不是第四个 Processing 状态 |
| Result / Issue / Back | 结果、恢复或用户退出 | 按各自冻结合同呈现，不由 Processing 重新定义 |

## 6. 需要可追溯的诊断字段

每次识别尝试应在现有日志/证据体系可支持的范围内关联以下信息，不得记录 Secret：

- attempt ID、原图引用/哈希、原图与归一化图像尺寸、EXIF 方向；
- 预处理变换及坐标映射版本；
- 检测模型版本、ONNX SHA、候选框、检测分数、候选数量；
- BBox 坐标系、像素框、Crop rectangle、尺寸/质量原因码；
- 分类模型版本、Top-K 结果、分类分数；
- 最终业务状态、决策原因码、每阶段耗时、错误类别；
- 测试报告使用的源码 SHA、数据集/模型版本与测试集标识。

上述字段是可追溯要求；具体存储位置、隐私规则与 API 字段仍由既有数据/API 合同控制。

## 7. 端到端验收矩阵

| 案例 | 预期检查 |
|---|---|
| 清晰单鱼、鱼体完整 | BBox 对齐；Crop 来源正确；分类器收到鱼体 Crop |
| 清晰无鱼场景 | 检测正常结束后进入 No Fish；不生成鱼获 |
| 模糊/过暗/解码失败 | 按真实质量原因或技术失败分流，不误报 No Fish |
| 远距离小鱼 | 尺寸门有可追溯原因码；不强行声称确定鱼种 |
| 鱼体触边/不完整入画 | 坐标与质量状态正确；不把不完整目标自动当成高可靠证据 |
| 多鱼场景 | 候选框及主目标策略可审计，不静默丢失目标选择语义 |
| 夜拍、黑底、黄色鱼 | 检查检测召回、BBox、Crop 与分类结果，不只看 UI 动画 |
| 竖拍/横拍/EXIF 旋转 | 预处理、BBox、Crop 使用一致坐标变换，无上下/左右错位 |
| Crop 越界或失败 | 返回技术错误或既有恢复原因，不伪装为无鱼 |
| 分类器低置信或候选接近 | 走现有 Low / Medium 判定合同；Top-1 不自动等同于用户确认 |
| 模型文件/ONNX 加载失败 | Technical Failure；记录版本和错误，不归因于照片 |
| 用户 Back / 重拍 | 退出当前 attempt；不使用旧图继续推理，不自动保存 |
