**状态：ACTIVE_CLOSURE / 等待视觉审议（非 Frozen）**  
**适用：设计系统与开发交接，不自动修改 Android**  
**关联：** [月 V2 原图](../assets/Record_Date_Month_V2.png) · [年 V2 原图](../assets/Record_Date_Year_V2.png)

## 1. 页面定位
入口是有数据首页统计条「记录天数」。页面回答“哪些日子去钓鱼、那天有什么真实鱼获”，**不是**鱼种分类、数据排名、游戏化签到或通用运营日历。标题为「记录」，顶部返回 / 今天；「月 / 年」分段切换复用相同页面状态，不开两个互不关联的 Activity。

## 2. UI 结构
| 层级 | 月视图 RD01 | 年视图 RD02 |
|---|---|---|
| Navigation | 返回 / 记录 / 今天 | 同一外壳 |
| Time Nav | 上月 / 2026年9月 / 下月 | 上年 / 2026年 / 下年 |
| Segment | 月选中 | 年选中 |
| Summary | 连续记录 / 本周 / 本月记录日数 | 全年记录日数 / 鱼获总次数 / 统计摘要 |
| Selector | 7列月历，星期一为首列，最多6周 | 4列×3行，1～12月 |
| Selected | 选中日期淡金细边 + 浅底，带真实计数鱼标记 | 选中月份淡金细边 + 浅底 |
| Detail | 选中日的 FishRecord 时间线与照片、鱼种、尺寸、地点 | 选中月份的日期集合列表，日期→进入选中日 |

### 月视图
- 月历按真实 Gregorian 日期计算，前后月灰阶区分，不能错位或填错星期。
- 每日鱼标反映实际鱼获条数，1条=1图标，上限5图标；第6条及以后需汇总显示，不可在窄格无限堆积。
- 选中日期下面的详情列表：真实来源照片 → 鱼名 → 长度/重量（有值才显示）→ 地点 → 时间。一天没有鱼获时使用节制空态，不虚构记录。
- 内容可以纵向滚动，严禁通过缩小字体把6周×N条鱼获压入一屏。
- 9月3日三条鱼获只是静态图演示，数量和鱼种数据以 FishRecord 真值为准。

### 年视图
- 年内月份始终 4×3、1～12月自然序，卡片“月名 / 有记录天数 / 鱼获条数”，无记录月份显示0（不是缺失）。
- 选中 9月显示下方9月全部日期记录，最新在前；日期列表使用真实鱼获缩略图，点击日期可进入该日。
- 顶部年度统计从完整年度有效记录计算；无记录不显示伪成长奖励。

## 3. 视觉与基础组件
**唯一背景母版**：`design/system/backgrounds/morning_lake_v1/assets/Morning_Lake_Master_V1.png`。  
**唯一变体**：`BG_DATA`（30% MistWhite veil、79% saturation、78% contrast、106% brightness、Global Blur OFF）。不可取两张生成图里湖景部分作为生产背景，也不可另造地貌、太阳、HDR 或新光源。

- 参考设计坐标：1080×1920 px；手机端按安全区和可用空间适配，绝不直接用像素定位。
- GLASS_A 日历/月份主卡、GLASS_B 统计与轻信息、GLASS_C 小范围文字保护；玻璃提供可读性，禁止厚重 HUD 边框。
- 字体只用 BRAND / DISPLAY / UI 角色，普通日期/数字可读性优先；DeepLakeBlue / Mist / 极淡 MorningGold，高亮金色只给“已选日/月”。
- 真实 FishRecord 照片优先；在设计稿中展示的 AI 生成鱼图**只是高保示例，不能当作真实钓获照片或模型训练证据**。
- 该界面没有捕获主按钮，也没有底部 Tab；回到首页或进入某条鱼获详情由已有导航处理。

## 4. 截图尺寸与原始文件政策
