## 1. 用户感知的一条连续镜头

首页点击 → 相机真实取景 / 系统相册 → 捕获或读取真实照片 → 同源照片初始承接 → 连续归位顶部 → 稳定首帧 → 四周水光唤醒、底部焦散 →（仅可信 Mask）真实鱼体金线逐渐绘制并保持高光 → 外围光收敛 → 同源照片进入 Result Hero → 中文鱼种名自然揭晓 → 静态可操作结果。

- **不设置拍照后的额外照片确认页面**，两种入口均直接归入识别。
- 相机拍摄不等待独立 AI 开场动画；相册选图不模拟快门。
- 所有真正识别结果只能来自当前 PhotoSession 的 Detector + Classifier；分割为可选光学能力。

## 2. 首页→相机（仅竖屏 UI）

- 点击现有首页主拍照 CTA：立即按压/高光响应，CameraX 初始化与轻量导航过渡并行启动。候选：按钮 60–120ms、页面 180–260ms、位移 ≤8dp；这不是相机初始化超时或必须等待的阻塞时长。
- 相机页主体是实时取景；保留返回、快门、系统相册入口；已有闪光灯/摄像头切换能力按仓库权威保留，不重复添加相同控件。
- 相机权限：已授权→真实预览；未授权→系统申请；拒绝→清楚的重试/设置路径；初始化慢→稳定中性状态且不冒充实时取景；失败→返回/重试。
- 首次拍照教学继续遵守现有冻结页面与真实触发条件，不把教学静态 PNG 当成 CameraX 预览。
- 快速连续点击应被去重；返回正确释放 Surface，不留下旧预览。
- V1 锁定竖屏布局，不支持横屏 UI，不以设备方向强制把横拍照片旋成竖图。

## 3. 两种照片初始承接

### 3.1 相机路径 C

C0 快门：立即触觉和轻微缩放反馈，不使用闪白/遮黑。  
C1 定格：**初始显示矩形=真实 CameraX 当前可见预览矩形**，尽量保留真实最后一帧；不能预先移动到屏幕中心。  
C2 捕获：真实文件保存/解码/EXIF 正向化；保留可信的定格画面作为视觉承接。无可用定格帧时只能保持稳定现有相机状态/中性过渡，绝不假造摄影画面。  
C3 原图接管：原图初始裁切和位置匹配 CameraX 预览的真实传感器→视图矩阵；可在 100–160ms 候选区间短暂交接，不得两个清晰照片叠影。  
C4 归位：从捕获预览可见矩形连续过渡到第 4 节统一顶部照片矩形；裁切源矩形从预览真实裁切逐步扩展至完整原图。  
失败：若捕获/文件/EXIF 处理失败，回到真实相机/重拍，不生成空 PhotoSession，不启动识别。

### 3.2 相册路径 G

G0 系统 Photo Picker 打开，取消则保持原页面，不创建新尝试。  
G1 选中 URI 后完成解码与 EXIF 正向化，构建真实照片身份。  
G2 初始承接矩形：宽 ≤0.88W、高 ≤0.68Hc，矩形中心 X=W/2、中心 Y≈0.44Hc；原图使用 Fit/Contain，不裁切。这个是**临时转场覆盖层**，不是第二个永久照片容器，超出下方面板空间时不得挡住可点击操作。  
G3 同源缩略图可先显示，完整原图就绪后原位替换，不允许先显示别的图片；无可用缩略图时保留稳定中性状态，绝不闪出上一张照片。  
G4 连续归位至第 4 节的唯一最终照片矩形；不播放相机快门白闪。

### 3.3 公共约束

- 相机/相册都使用一个原图 Bitmap/Source ID 作为可见照片权威；转场覆盖层不得在底图之外持续叠加第二张清晰照片。
- 归位过程中插值 **位置、尺寸、真实裁切/完整视野、圆角**；禁止由 CenterCrop 硬切到 FitCenter。
- 照片按实际可见帧就绪条件驱动，时间候选只用于调优：相机定格 80–120ms、归位 320–420ms；相册承接 100–160ms、归位 280–360ms；到位稳定 100–160ms。
- 照片到位、解码完成、方向统一、首帧确实呈现后，才启动依赖最终几何的 SWOS；真实模型可更早并行推理。

## 4. 最终竖屏 Processing 几何（唯一目标）

定义：W/Hc 为扣除系统 Insets 后的 **内容区 dp 宽高**；相应照片 iw/ih 为 EXIF 正向化后的原图像素宽高。所有坐标先统一至同一 dp/px 体系后计算，不混用像素矩形与 0–1 矩形。

- 顶部返回/导航：参考 52dp，允许 44–56dp；照片区位于导航下方 16dp。
- 照片左右边距：≥16dp；最大可用宽度 Pw=W−32dp。
- 下方唯一识别面板：参考高度 88dp，底部安全区上方约 20dp，照片/面板间距≥20dp。
- 照片最大高度 Ph=max(0,min(0.52Hc, Hc−navHeight−16dp−20dp−panelHeight−20dp))。不足空间时优先调整可调间距/照片上限，绝不压缩或遮住返回、底部面板、系统 Insets。
- s=min(Pw/iw,Ph/ih)，显示图片宽 Piw=iw·s、高 Pih=ih·s；left=(W−Piw)/2，top=navHeight+16dp（内容区坐标）。
- **完整原图 Fit/Contain**，不裁鱼头鱼尾、不拉伸、**不在照片背后叠加同源模糊扩展图**。照片比较窄/矮时由普通页面底色承接自然留白；四周光严格贴合实际 Piw×Pih 边界，不贴外部容器。
- 不同比例统一算法：3:4 竖图、9:16 长竖图、1:1 方图、4:3 横图、16:9 超宽图、极端比例均不另建页面。
- 在小屏 320×480、360×640 和常用 390×844、430×932（内容区 Insets 单独扣减）检查安全区域、触控尺寸和照片可见性。
- 相机页和 Processing 均锁定竖屏 UI；**输入横向照片合法**。相机照片、相册 EXIF 仅正向化一次；Detector/BBox/SlimSAM/RR09 统一引用正向后的来源坐标；缺失 EXIF 不得靠设备握持姿势猜测旋转。

## 5. Processing 页面信息密度与光效边界

- 视觉主体：上方真实照片。下方只有 **一个精致小面板、一个克制的动态标记、固定“识别中”**。不出现四步列表、技术名称、阶段叙述、虚假百分比、假剩余时间或未确认鱼种。
- 小型识别符号固定在下方面板内，不向照片中央扩张；它与禁止的照片中央放大圈不是同一效果。
- 四周水光使用三色：深海孔雀青 #0B6E69、清透水绿 #4DD0C7、冰白 #DDF7F5；用真实照片边缘空间坐标与透明混合，不整体染色，不覆盖鱼眼/鱼鳞。该色组替代当前 Android 识别链路中被否决的旧边缘蓝绿金配色；不篡改历史旧稿。
- 向上焦散：底部向上不规则水光纹理，自然展开、衰减；不得使用横跨全图粗光带、中心环形扫描或雷达线。
- 实际移除/禁止 **两处** 中央圆环源：水波共振扩张椭圆脉冲，以及 FishFocus B/C 不可信 Mask 的环形降级。不是单纯减弱 Alpha。
- Mask 可信（TRUSTED_MASK 且 quality=GOOD，身份、ROI、尺寸、映射、轮廓检查全部通过）→ 根据真实鱼体轮廓逐段绘制 Core/Soft Glow/Halo 暖金线，并给予稳定高光。不得把 BBox、椭圆、固定鱼形当作 Mask。
- Mask 缺失/迟到/不可信（含 WARNING/INVALID、身份不一致）→ 完全不绘鱼体专属形状，不加替代光圈；四周水光和焦散继续；主分类成功仍可转场并揭晓名称。
- 可信 Mask 高光与 SWOS 四周水光独立可用：光场失败保留照片；Mask 失败不会关闭环境光。

## 6. 事件驱动的自适应视频节奏

本旅程冻结 **视觉阶段顺序、进入/退出门、最低可感知表现**，而非固定 2800ms 到点跳页。初始量化窗口如下，真实视频校准不得改变产品行为或制造重复高潮。

| 视觉段 | 进入 | 最短可感知表现候选 | 退出 |
|---|---|---|---|
| S0 照片稳定 | 真实原图首帧、归位结束、几何有效 | ≥180ms | 照片稳定、无黑帧 |
| S1 四周光唤醒 | S0 完成 | ≥500ms | 水光自然渐入 |
| S2 向上焦散 | S1 已开始（允许并行交叠） | ≥700ms | 有清晰的上行、变化、衰减 |
| S3 Mask 轮廓 | TRUSTED_MASK 在接纳窗口到达 | ≥750ms | 真实轮廓逐段形成，不瞬现 |
| S4 轮廓高光 | S3 完成 | ≥450ms | 完整暖金保持，允许外圈退场 |
| S5 光场收敛 | 主要水光完成（有 Mask 时 S4 已开始） | ≥350ms | 外围水光自然归零 |
| S6 RR09 | 真实主模型结果+必要视觉完成+目标几何就绪 | 目标 850ms（非固定 Processing 结束线） | 同源照片 Hero 交接且中文名揭晓 |

- Mask 未在本轮 S3 接纳门前以可信状态就绪 → 采用无 Mask 分支：S1/S2 自然完成一次边缘光学峰值后收敛，**不等待分割模型、不会临时插入迟到金线**。原提议“1800ms”仅首轮观测参数，未冻结为产品超时真理。
- 真正 Detector/Classifier 很快：必须完成必要的可感知视觉阶段再转场；真实模型慢：稳态低扰动等待，**不反复重播高潮**，不假报成功；运行失败明确退出为失败/重试。
- 初始化软警告 8s、初始化失败保护 20s、主推理软警告 8s、失败保护 15s、Mask 接纳观察 1800ms 均为工程首轮**校准候选**，不得未经实测把它们冒充已验证的模型超时标准。
- 动效时钟起点是照片归位后首帧**实际呈现**的单调时间；模型时钟独立运行。禁止照片暗屏期间偷偷耗掉 Processing 视觉时间。

## 7. Result / RR09 照片唯一所有权与降级

- 主分类结果真实可用、当前 session 有效、必要视频阶段完成、Hero 布局/几何真实可用后，才允许启动 RR09。
- RR09 目标仍为 **850ms**；R0/R0.5/R1/R2/R3/R4/R5 继承冻结相对编排。**R0.5=照片移动段 0–200ms 的真实几何中点，目标约 100ms，不是总 RR09 850ms 的半程 425ms**。未经产品批准不重定义该关键帧。
- 迁移期间只允许 **一张清晰真实照片** 可见；同源照片由唯一共享层运动至 Result Hero，最终 Hero 在交接成功前不得再次绘制清晰副本；不能同时叠加整页导航缩放产生第二张照片。
- 目标 Hero 保留现有结果页两种策略：可靠 BBox 时安全裁剪、不可靠或不安全时 FULL_SOURCE_FIT_SAME_SOURCE_AMBIENT；**Result Hero 可以使用同源模糊背景填充**，这不等同 Processing 阶段禁用的模糊扩图。缩放过程中背景/圆角/裁剪同源、无跳帧。
- PhotoCropRect **像素** 转 NormalizedSourceRect **0–1** 必须显式除原图宽高；EXIF/裁剪/Mask/照片共享变换使用一个 M(t)。
- 可信 Mask 且满足现有 HIGH 揭晓条件 → 暖金轮廓可按既有 RR09 空间轨迹转译至**真实中文名称**，R5 无光效残留；不可信或缺失 → 仍完整进行照片落位与中文名自然揭晓，**不编造空间金光轨迹**。
- Medium/Low/NO_FISH/IMAGE_QUALITY/TECHNICAL_FAILURE 保持既有结果资格与错误路由，不能为展示动效强行当作 HIGH 成功；模型失败不渲染假中文鱼种。
- RR09 几何首次未就绪时，不得先跑时钟再迟到播放；若无有效几何，使用同源原图 FIT 静态安全交接，明确记录降级，不跳图、不重复触发。
- 整条流转可以在未完成真人视觉验收前生成候选 APK，但不得标注视觉 PASS。

## 8. 生命周期、失败和可访问性

- 取消、重试、切照片、返回、权限拒绝、相机失败、图像读取失败、EXIF 异常、慢推理、后台/前台、Surface 释放、Reduced Motion 都保留相同 session 隔离与停止语义。
- PhotoSession 新建尝试后，旧 Detector、Classifier、SlimSAM、GPU、纹理、定格帧和 RR09 回调必须失效；不复播已完成的揭晓。
- Reduced Motion：保留真实照片、极简状态与中文结果，不执行强空间位移、闪烁或粒子轨迹；不阻碍操作和系统权限。
- 视觉失败/超时不能以持续“识别中”冒充成功；用户可重试、返回或重新选图；失败具体技术日志不得泄露敏感照片内容。
