# R06 · 失败边界 · 生成规范 V1

状态：**失败边界 FROZEN / 不要求主动生成新反例图**

归属：

`识别过程 → 03 · 图层与组件归属 → AI 边缘光场 V1 → 03 · 视觉参考集 → R06 · 失败边界`

## 1. 目的

建立清晰的视觉红线，让任何人不看参数也能识别“这已经不是渔见 AI 边缘光场”。

## 2. 画面形式

不要求重新生成六宫格。优先复用已有被否决候选图或真实 Runtime 失败截图，并按 F01–F06 单独归档。

## 3. 构图要求

- F01 · 闭合霓虹边框
- F02 · 雷电 / 魔法能量
- F03 · HUD / 扫描器
- F04 · 平行铁路式 Hairline
- F05 · 四角等亮 / 对称
- F06 · 过弱 / 几乎不可见

## 4. 视觉重点

- 每个反例必须一眼看懂哪里错
- 反例只用于建立边界，不追求好看
- 要覆盖“过强、过科技、过规则、过对称、过弱”五类常见问题
- 必须让 QA 能据此快速判定是否需要返工

## 5. 必须保持

- 每个反例仍基于真实照片场景，方便直接比较
- 错误点要单一明确
- 反例标签只描述问题，不给实现建议
- 至少包含一个‘过弱到失去 AI 存在感’的反例

## 6. 明确禁止

- 把失败案例做成新的视觉创意方向
- 在同一案例里同时塞多个错误导致无法判断
- 把运行时性能问题当视觉失败边界
- 把 Fish Focus 错误混进只针对 Edge Field 的案例里，除非明确标注

## 7. QA 使用方式

R06 的六类标签直接用于开发验收：

- F01 · 闭合霓虹边框
- F02 · 雷电 / 魔法能量
- F03 · HUD / 扫描器
- F04 · 平行铁路式 Hairline
- F05 · 四角等亮 / 对称
- F06 · 过弱 / 几乎不可见

实际开发中一旦出现上述问题：

1. 截取真实 Runtime 图；
2. 标记对应 F 编号；
3. 作为失败证据归档；
4. 修复后与同一状态重新对照。

已有被否决设计候选若正好表达某个失败类型，也可直接复用。
