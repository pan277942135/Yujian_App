## 3. 不同水域的视觉设计约束

### A · 鱼缸 3 级

- **主体：容器中的真实鱼获记忆。** 鱼缸的玻璃曲率、折射、水线与鱼群层级是主视觉；整体不要被统计面板和按钮覆盖。
- **圆缸：** 延续手机竖屏构图，保留单一圆形玻璃缸、水草与底砂的真实质感；5鱼为示例，不是进阶阈值。鱼缸与背景有明确边界。
- **方缸：** 横屏可展开更完整的水域，保留上沿、侧壁、底边，避免退化为没有边界的自然鱼塘。鱼的前后层级自然、局部遮挡可信；拥挤时优先视觉可读性。
- 历史稿中的**皇冠、“最大鱼”奖杯与夸张金边**不能直接继承为最新设计。可以保留自然观察中的主鱼焦点，禁止以游戏化徽章表达成就。

### B · 鱼塘 5 级

- **主体：自然独立水域而非玻璃容器。** 用真实岸线、水草、浅滩、石块、水面与水下环境表现鱼从鱼缸走入自然。
- 横屏水上/水下并置可以作为设计构图方向，但水体透明度和鱼体大小不应变成夸张景观海报。
- 已归档阶段语义保持：单池 → 横向长塘 → 深浅分区 → 主塘与浅湾 → 完整曲湾。

### C · 湖泊 7 级

- 当前只有已经归档的湖泊1–7对比阶段板，**不要把鱼塘或鱼缸草稿当作湖泊最终高保**。
- 维持第2阶段内凹双浅湾，第4阶段水中陆岬/半岛分水；其余按现有`My_Habitat_Spec_V1.md`延续。

## 4. 公共视觉系统优先级

1. **真正的鱼获身份：** 每条展示鱼只能对应一个真实 `FishRecord/FishInstance` 的鱼体资产。历史AI高保中的鱼为示意，禁止将其当作生产鱼体图；长度比例以记录数据为依据。
2. **Morning Lake 背景：** 当前我的鱼获/资料页继续使用冻结 `Morning_Lake_Master_V1 / BG_DATA`。数据页处理参数为 MistWhite 30%、Saturation 79%、Contrast 78%、Brightness 106%、Global Blur OFF。
3. **沉浸水域场景：** 圆缸/景观方缸/鱼塘可表现独立“被记忆承载的水域”，但历史图中的第二个太阳、强金色HDR和与公共背景矛盾的山水不构成新共享背景权威。不得从历史PNG直接抠出湖景覆盖全局母版。
4. **字体与玻璃：** 沿用 Core Visual V1 的字阶、低干扰玻璃和可读性；优先显示鱼体与真实记忆而非仪表盘。
5. **动效/视频：** 可以在设计中规划缓慢鱼游、低频水纹及景深，但**目前没有本十张图对应的已冻结原始视频资产或逐帧动效合同**，不得把静态高保形容成已交付视频。
6. **内容统计：** “5条鱼获/3种鱼”“28条/8种”都只是历史样例值。鱼获数=记录条数，鱼种数=不同鱼种去重数；不添加游戏化积分/皇冠数值。

## 5. 10张原始PNG正式入库门槛

所有文件必须是 **原始字节，无重新编码、尺寸修改或视觉生成替换**：

1. 取得每张文件授权的原始文件内容，核对 `PNG Signature = 89 50 4E 47 0D 0A 1A 0A`。
2. 读取IHDR尺寸并校对上述原始宽高；核对实际字节数与Library元数据。
3. 从原始完整二进制计算 **SHA-256**，按 `reference/recovered/` + 稳定的英文标识文件名入 Git。
4. 读取远端文件再次比对Git blob SHA、实际原始文件SHA-256、宽高、字节数。
5. 更新 `recovered_hifi_sources_v1.json` 的 `git_asset_path`、`image`、`sha256`、`git_blob_sha` 和 `raw_binary_status: COMMITTED_VERIFIED`，并在 Design Manager 中让源图可点开原始PNG；保留原Library文件名作为 `source_filename`。
6. 任一文件拿不到完整原始字节，**只保持 `NOT_MATERIALIZABLE_NO_GIT_UPLOAD`**，不可声称成功；部分可用也必须逐图分别标记。
7. 在未经过用户对主页面高保的最终审核前，仍然保持 `DESIGN_ONLY`，不改成 `FROZEN`。
