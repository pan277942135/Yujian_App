# 渔见｜鱼获图片自适应显示设计 V1.1

**状态：FROZEN — 当前公共设计权威**  
**生效日期：2026-10-20**  
**系统 ID：fish_media_display_v1**  
**替代关系：V1.1 在图片容器响应式几何、BBox 安全裁切顺序及失败回退方面取代 V1 的冲突规则；V1 原文仅保留为历史版本。**  
**重要：设计规则冻结不等于 Android Runtime 或真机验收通过。**

## 1. 冻结目标与范围

在不因照片横竖方向改变同类卡片宽高比的前提下，尽可能完整地展示真实鱼体；图片区域必须铺满容器，不出现黑边、纯色留白、突兀灰色矩形边框或非等比拉伸。

本规范适用于：
- NH01 首页最近鱼获卡片、轮播卡片及 HOME 共享 Hero；
- AI 识别结果页图片；
- 鱼获详情 A 面 Hero 与编辑状态图片；
- 我的鱼获列表缩略图的主体裁切与失败回退。

页面既有信息架构、文字、CTA、圆角及状态结构不在本次范围内。各组件继续使用自己的既定参考比例；本规范不要求所有组件共用同一个比例。

## 2. 容器几何：屏幕响应，比例稳定

### 2.1 通用原则

1. 卡片宽度根据当前窗口的可用内容宽度、页面边距、列数及间距响应。
2. 同一组件的卡片宽高比保持稳定；不得因照片是横拍或纵拍而动态切换卡片比例。
3. 卡片高度由实际卡片宽度和该组件既定宽高比计算：height = width / aspectRatio。
4. 屏幕变宽时卡片可以随之变宽、变高；屏幕变窄时卡片相应缩小。不得把单一设备的像素宽高硬编码为所有设备的固定尺寸。
5. 遵守系统安全区和现有页面边距。大屏使用现有最大内容宽度约束；若当前组件没有最大宽度定义，实施前登记建议值并保持组件内部一致。
6. 首页最近鱼获卡片和轮播卡片可以使用各自已经冻结的比例；轮播相邻卡片露出比例和滑动行为保持稳定。
7. 识别结果页保留各结果状态现有的参考几何。容器宽度可随可用屏幕宽度响应，但比例由结果状态决定，不由照片方向决定。
8. 详情／编辑 Hero 保留当前组件的参考比例，并按可用宽度响应；详情正文可以自然滚动，不让 Hero 无限增高。
9. 图片的横竖方向、BBox 形状和位置只影响裁切窗口及主体定位，不改变同类卡片的几何比例。
10. 布局使用 dp，文字使用 sp。系统字体缩放、Edge-to-edge、手势导航和三键导航均须纳入测试。

### 2.2 首页 Hero 的参考尺寸

HOME Hero 现有 740×880 仅作为设计参考画布，其宽高比为 740/880，不是所有手机上固定使用的物理尺寸。运行时应根据可用宽度响应，并保持该参考比例。详情 Hero 如有独立的现有冻结比例，则保留详情自身比例，不得为了统一比例而擅自改动。

### 2.3 小屏与内容溢出

- 不因照片横竖方向改变卡片比例。
- 识别结果页在短屏或大字体下允许内容区域滚动；主要操作不得被系统导航区遮挡。
- 详情／编辑页正文和表单自然滚动。
- 图片加载中、加载完成和缓存命中时，容器几何保持稳定，避免闪烁或跳动。

## 3. 原图与方向坐标

1. 原始图片字节永久保留，任何裁切、缩放、背景模糊或合成只生成展示衍生结果，不覆盖原图。
2. 先处理 EXIF Orientation（包括旋转与镜像），再将 BBox 转换到归一化后原图的坐标空间。
3. BBox、鱼体安全区域和裁切窗口必须使用同一坐标系。
4. 禁止非等比拉伸、生成式补画、鱼体修复、无关图库替换，以及将分类器输入裁切图冒充用户原图。
5. 裁切只改变 presentation；原图和检测 BBox 不得被裁切窗口覆盖。

## 4. BBox 可信度

BBox 只有在以下条件成立时才可用于主体裁切：
- 框存在且坐标合法；
- 面积大于零，且框位于有效原图范围；
- 检测结果来源可信，坐标与 EXIF 方向一致；
- 多鱼场景的主体范围可被可靠确定；
- 不存在明显异常的框尺寸或宽高比。

优先沿用识别管线已有的可信标记。若没有展示裁切专用阈值而存在可用检测置信度，V1.1 初始阈值为 **0.65**，必须配置化。该阈值仅控制展示裁切是否安全，不得改变模型推理、分类、NMS 或识别门禁。若置信度缺失，只允许使用已明确标记为可信且通过几何校验的 BBox。

BBox 缺失、不可信或多主体无法判定时，不执行激进裁切，直接进入同源背景填充兜底。

## 5. 冻结的裁切优先级

严格按以下顺序，不得提前跳过步骤：

**BBox 锚定扩展 → 边界单侧补偿 → 逐步缩小安全留白 → 合法裁切；仍不可行时才同源背景填充。**

### 5.1 初始安全边距

以可信鱼体 BBox 为锚点向四周扩展：
- 水平边距：BBox 宽度的 10%；
- 垂直边距：BBox 高度的 12%；
- 可设置最小像素边距，防止极小 BBox 产生不稳定结果。

扩展后的主体区域不得超出原图边界。

### 5.2 单侧补偿

某一侧到达原图边界时：
1. 停止向该侧扩展；
2. 计算该侧缺失的扩展量；
3. 将剩余扩展量转移到相反侧；
4. 水平方向和垂直方向分别执行；
5. 重新检查目标比例、BBox 完整性及原图边界。

鱼体贴边本身不等于裁切失败。禁止仅因贴边就直接回退，也禁止通过虚构画面或非等比缩放补足空间。

### 5.3 逐步缩小安全留白

如果初始边距和单侧补偿后仍无法得到合法裁切窗口，依次尝试以下边距配置：
- P0：水平 10%，垂直 12%；
- P1：水平 8%，垂直 8%；
- P2：水平 4%，垂直 4%；
- P3：水平 0%，垂直 0%。

每次都必须重新执行边界补偿和裁切窗口计算。不得为保留固定留白而过早放弃裁切，也不得为了达到零留白而切掉有效鱼体。

### 5.4 目标比例与合法窗口

原图尺寸为 W×H，目标卡片宽高比为 r，扩展后的主体区域宽高为 bw、bh。最小候选窗口：

- cropW = max(bw, r × bh)
- cropH = cropW / r

窗口必须完整容纳有效鱼体 BBox 和当前安全边距，且不得超出原图。若窗口宽度大于原图宽度，或高度大于原图高度，或像素取整后安全校验失败，则该轮不合法。

裁切位置优先保证鱼体完整，尽量接近视觉中心；当鱼体靠近某一侧边缘时，应根据可用空间调整窗口，不使用固定中心裁切作为唯一策略。

### 5.5 裁切验收

裁切输出必须满足：
- 有效 BBox 完整位于裁切窗口内；
- 窗口在原图边界内；
- 输出比例与目标容器一致；
- 不发生非等比缩放；
- 像素取整后再次通过全部安全检查。

只有通过以上检查，才允许使用主体裁切填充。

## 6. 最后兜底：同源模糊背景填充

触发条件：
- BBox 缺失或不可信；
- 完成单侧补偿与所有留白级别后，仍无合法裁切窗口；
- 极端宽高比或安全检查失败；
- 直接裁切会损害有效鱼体。

### 背景层
- 使用同一张原图；
- 等比例覆盖容器；
- 适度高斯模糊，并根据画面适度降低对比度；
- 背景必须覆盖整个容器，不露出纯色或空白区域。

### 前景层
- 保留完整原图，等比例缩放；
- 前景作为清晰、主导的主体层；
- 边缘可渐进融合以降低矩形拼接感；已知鱼体区域不得被边缘羽化侵蚀；
- 不得裁掉原图鱼头、鱼尾或关键证据。

### 合成结果
- 输出尺寸符合容器比例；
- 前景和背景均来自同一张原图；
- 不出现黑边、纯色留白或突兀灰色矩形边框；
- 不改变鱼体比例；
- 背景仅是展示衍生层，不代表真实新增场景。

禁止使用生成式 AI 扩图、inpainting、生成鱼体或生成额外环境。若原图解码失败，使用统一错误占位图并记录原因。

## 7. 页面映射

| 页面 | 容器几何 | 首选方式 | 兜底方式 |
|---|---|---|---|
| NH01 最近鱼获卡片 | 宽度按屏幕响应；本组件比例稳定 | 可靠 BBox 锚定裁切 | 完整原图前景 + 同源模糊背景 |
| NH01 轮播卡片 | 宽度、露出比例响应；本组件比例稳定 | 可靠 BBox 锚定裁切 | 完整原图前景 + 同源模糊背景 |
| AI 识别结果 High/Medium/Low | 保留结果状态既有比例；宽度按可用空间响应 | 可靠 BBox 锚定裁切 | 完整原图前景 + 同源模糊背景 |
| No Fish / Image Quality | 保留状态既有比例；宽度按可用空间响应 | 不执行鱼体 BBox 裁切 | 完整原图前景 + 同源模糊背景 |
| 详情／编辑 Hero | 保留本组件既有比例；宽度按可用空间响应 | 可靠 BBox 锚定裁切 | 完整原图前景 + 同源模糊背景 |
| 我的鱼获列表缩略图 | 沿用现有 82dp×82dp、1:1、R14dp 规格 | 可靠 BBox 锚定裁切 | 完整原图前景 + 同源模糊背景；源图不可用时中性占位 |

识别结果页和详情页显示的裁切图只影响展示，不得改变模型输入或记录原图。No Fish / Image Quality 不推测鱼的位置；完整原图必须保持可见，背景填充只负责填满容器。

## 8. 缓存、稳定性与诊断

展示衍生图缓存键至少包含：原图内容标识/版本、目标比例、BBox 数据版本、算法版本、背景参数版本。任一关键参数变化时重新生成。

不得在每次列表重绘时重复完整图像处理。图像处理应在后台执行，加载状态下容器几何保持稳定。

诊断记录至少包含：
- 原图标识、尺寸、EXIF 方向；
- BBox 来源、置信度、坐标系及有效性；
- 使用的边距级别；
- 最终裁切窗口；
- 选择的展示模式；
- 回退原因；
- 算法版本和处理耗时。

日志不应无必要地复制或长期保存完整原图。

## 9. 验收矩阵

覆盖 320dp、360dp、393dp、430dp；产品支持时覆盖 ≥600dp 大屏；系统字体 1.0×、1.3×、1.5×；手势与三键导航；Edge-to-edge 与安全区。

照片场景至少覆盖：
- 横向、纵向、近方形；
- 极端横向 ≥3:1、极端纵向 ≤1:3；
- 鱼体贴左、右、上、下边缘；
- 鱼体接近占满原图；
- 多鱼；
- BBox 缺失、不可信或异常；
- EXIF 旋转及镜像；
- 低分辨率、真实夜景、嵌入黑边、解码失败。

验收必须区分真实 Android 真机、模拟器和静态 CSS 示意。静态设计演示不得作为真机证据。对可信 BBox 且几何上可行的样本，鱼体完整率要求 100%；整体视觉可接受率目标为 95% 以上。检测器漏检或错误 BBox 不计作裁切算法准确率，但必须正确触发安全回退。

## 10. 冻结声明

V1.1 冻结的是产品规则、容器响应式原则、裁切顺序、回退方式、原图保护和验收要求。开发团队可按现有 Android 技术栈实现，但不得改变以上行为。

设计冻结不等于代码已实施、APK 已构建或真机已通过。任何改变容器比例策略、裁切优先级、原图保护、背景兜底或验收标准的需求，必须通过新版本变更评审。
